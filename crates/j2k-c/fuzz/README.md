# j2k-c fuzz targets

Two targets cover the C ABI paths added by the persistent decoder and the
header-fact whole-image route.

| Target | Focus |
| --- | --- |
| `c_full_route_differential_fuzz` | Full-image layout agreement, explicit core route versus batch pixels (default full-image decode and a forced-batch region request), inter-row padding, short-buffer and invalid-stride errors, and rejection-path parity |
| `c_decoder_lifecycle_fuzz` | `open`/`feed`/`transfer_syntax`/`close`, second decode parity of held codestreams, transfer syntax class validation (`J2K_SYNTAX_JPEG2000_LOSSLESS`..=`J2K_SYNTAX_OTHER`), rollback after a rejected feed, captured input limits, null-handle close |

The input of each target is a complete codestream. Seed files stay valid from
their first byte; the differential target uses the input length only to choose
inter-row padding. Both targets set `workers: 1` and a 4 MiB output cap so a
mutated header cannot turn a run into an out-of-memory test.

## Seeds

The six seeds copied from `crates/j2k-native/fuzz/corpus/native_decode_fuzz/`
are synthetic codestreams generated by the repository's encoder. They cover
classic and HTJ2K, gray and RGB, 1/8/12/16-bit samples, tiles, layers, PLT/TLM,
SOP/EPH, and reversible and irreversible transforms. `c_decoder_lifecycle_fuzz`
also embeds the 16x16 HTJ2K RGB8 seed as its baseline codestream.

`classic_gray8_nonzero_origin.j2c` is a minimized codestream from the
differential target's first CI run. It is a valid 53x2 gray 8-bit image whose
reference-grid origin is `(0, 14)`; it exposed a core-versus-batch sample
disagreement at a few positions, since fixed in the reversible 5/3 inverse
transform. The differential target now compares both routes on it like any
other representable codestream, and still exercises the rejection path for
layouts the native route does not represent by asserting that `decode_full_into`
matches `output_info_native`'s rejection status and leaves caller canary
buffers untouched.

## Running

From this directory:

```sh
cargo +nightly fuzz run c_full_route_differential_fuzz -- -runs=1000
cargo +nightly fuzz run c_decoder_lifecycle_fuzz -- -runs=1000
```

The workspace wrappers run both targets:

```sh
cargo xtask fuzz-build
cargo xtask fuzz-run
```

`J2K_FUZZ_RUNS` and `J2K_FUZZ_MAX_TOTAL_TIME_SECONDS` control the smoke and
long runs used by CI.
